Markdown 导出

这一节最重要。3.4 / 3.5 / 3.6 请务必实测——它们保护的是你现有的手写工作记录。

一件我必须说清楚的事

设计文档里我原本写导出「绝不覆盖」。codex 两轮审查都指出这条做不到绝对成立： POSIX 没有「校验内容并替换文件」的原子操作，flock 只是劝告锁，管不住任意外部编辑器。

我把窗口压到了几十微秒（内容先写进临时文件并 fsync，锁内只做「复核 hash + rename」两步）， 并把自动导出默认关掉。但残余竞态是真实存在的，我不打算说成已解决。 你现有的手写文件是安全的（3.6 有测试守着），风险只存在于 Gong 自己生成的那些文件上。

Ribbon 只读 拖拽调整不在 v1 范围 改时间在下方两列文本框里改

08

刻意如此的四件事

来自周岭《认知觉醒》。这是产品约束不是风格——改了会让这个 app 变成制造愧疚的机器。

原则在 app 里的样子为什么
用记录代替打卡仪表给「上次中断的日期」，不给连续天数 打卡 → 认知闭合 → 应付 → 放弃 → 愧疚
设下限不设上限下限的标准是「再累也做得到」 下限太高就不是下限，是伪装成下限的上限
少即是多下限 / 最重要各限一条，UI 不允许加第二条 把约束写进数据模型，而不是靠自觉
中性不评价状态是「已完成／未记录」，无 ✓ ⚠ 感叹号鼓励语 false 读作失败，notRecorded 读作事实
最后一句

愧疚是 N-1 触发器的燃料。这个 app 唯一不能做的事，就是让你因为它而更自责。
