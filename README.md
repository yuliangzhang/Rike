# 工字表 Gong

macOS 桌面挂件式每日「工」字表 + 注意力阻断器 + 软件使用时长监控。

```
┌──────────────────────────────────────┐  工 · 上横（通栏）
│ 今日 TODO      ◀ 2026-09-01 周二 ▶   │  下限 ⌂ / 最重要 ★ 各限一条
└──────────────────────────────────────┘
   ┌────────────────────────────────┐    工 · 中竖（内缩 → 工字剪影）
   │ 横排时间轴：上轨计划 / 下轨实际  │
   ├───────────────┬────────────────┤
   │ 计划           │ 实际            │
   └───────────────┴────────────────┘
┌──────────────────────────────────────┐  工 · 下横（通栏）
│ 今日总结：触动 · 模糊清单 · 状态       │
└──────────────────────────────────────┘
```

## 快速开始

```bash
./scripts/build.sh      # 编译 + 组装 .app + ad-hoc 签名 → build/Gong.app
./scripts/install.sh    # 安装到 /Applications
swift test              # 59 项单元/集成测试
```

无 Dock 图标（`LSUIElement`），从菜单栏「工」图标进入主窗口。

## 三条值得知道的设计取舍

**1. 时间轴用 elapsed 轴，不用墙钟轴。**
秋令时当天 01:30 出现两次，墙钟轴会把两个不同的真实区间画到同一位置；
elapsed 轴天然分开，轴长也等于当日真实时长（春令时 1380 / 秋令时 1500 分钟）。
计划块是墙钟意图，先换算成真实 instant 再投影；春令时被跳过的时刻标虚线。
全部逻辑在 `DayTimelineProjection`，纯函数，有 DST 前跳/回拨/跨零点/跨时区测试。

**2. Markdown 导出宁可不写，绝不覆盖。**
目标不存在 → `O_EXCL` 独占创建；已存在 → 必须同时满足「有生成标记」和
「内容 hash 等于上次导出值」才替换，且在 `flock` 内、rename 前再复核一次；
否则一律另存 `*.gong-conflict.md`，原文件一字不动。
**这个竞态无法对不合作的外部进程彻底消除**——`flock` 是劝告锁。
自动导出默认关闭，就是为了把撞上的机会压到最低。

**3. 使用统计是事件日志的纯函数产物。**
监控只写 append-only 的 NDJSON 事件；统计随时可重建、幂等。
崩溃时按最后一条 heartbeat 截断并标记 `truncated`，不凭空外推。
跨零点的区间靠读 D-1/D/D+1 三天窗口再按日切分。

## 四条写死的产品原则

来自周岭《认知觉醒》。这是产品约束，不是风格：

1. **用记录代替打卡** —— 仪表给「上次中断的日期」，不给连续天数。
2. **设下限不设上限** —— 下限的标准是「再累也做得到」。
3. **少即是多** —— 下限/最重要各限一条，约束写进数据模型。
4. **中性不评价** —— 状态是「已完成／未记录」，没有 ✓ ⚠ 感叹号鼓励语。

理由：打卡 → 认知闭合 → 应付 → 放弃 → 愧疚，而愧疚正是 N-1 触发器的燃料。
一个做成打卡的 app 会亲手把使用者送回失控。
